# Разработка клиентской части модуля «Накопительная ведомость»

## Тема проекта
Разработка клиентской части модуля управления накопительными ведомостями логистической компании.

## Назначение системы
Модуль «Накопительная ведомость» предназначен для просмотра, проверки и обработки накопительных ведомостей, а также для работы с журналом сборов, результатами автоматических правил и ручными операциями по документам.

## Цель разработки
Автоматизировать работу сотрудников компании по просмотру и проверке документов, сократить количество ручных действий, повысить прозрачность процесса согласования и обеспечить удобную работу с большими таблицами и карточками документов.

## Основные пользователи
- **Коммерсант** — просматривает журнал НВ, карточку документа, правила, историю и связанные документы.
- **Согласующий** — выполняет те же действия, что и коммерсант, и дополнительно может подписывать или отклонять документы.
- **Инженер сопровождения / администратор** — контролирует работоспособность системы, интеграции и корректность обмена данными.
- **Смежные системы** — АСУ-АСУ, модуль автосогласования, интеграционный модуль / ЭТРАН.

## Ключевые функциональные требования
1. Отображение журнала накопительных ведомостей с фильтрацией, поиском и сохранением пользовательских представлений.
2. Отображение результатов применения правил автосогласования в журнале и карточке НВ.
3. Поддержка карточки НВ со вкладками «Документ», «Правила», «Связанные документы», «История».
4. Поддержка режима «Сборы» с журналом начислений и переходом к деталям.
5. Выполнение ручных операций по документу: подписание и отклонение.
6. Поддержка групповых операций над несколькими документами.
7. Выгрузка данных журналов в Excel.
8. Получение справочников и нормализованных данных из смежных подсистем.
9. Публикация и потребление данных через GraphQL API.
10. Обработка ошибок интеграций и отображение актуального статуса операции пользователю.

## Ключевые данные
- нормализованные данные НВ;
- данные по решениям правил из модуля автосогласования;
- справочники документов, станций, организаций, форм и мест оплаты;
- операции по документам, результаты операций и история действий;
- данные по сборам, налогам и статьям начислений.

## Нефункциональные требования верхнего уровня
- **Производительность:** быстрый отклик при работе с большими журналами и сложными фильтрами.
- **Надёжность:** защита от повторного выполнения операции и согласованность статусов.
- **Безопасность:** разграничение прав доступа по ролям.
- **Трассируемость:** аудит пользовательских и интеграционных действий.
- **Удобство использования:** предсказуемая навигация, понятные статусы и минимальное число лишних действий.
